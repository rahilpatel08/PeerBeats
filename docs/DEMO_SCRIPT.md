# Lab demo script (about 8 minutes)

**The one sentence:** "Users power the network, and subscribers fund it."

## Before the audience arrives

1. Double-click **PeerBeats** (the Mac app) or **Start PeerBeats**. The Lab page opens. Keep it running.
2. Plug the laptop in. Turn off sleep and notifications.
3. **Check the Mac has internet.** Phones reach it through the phone link, which needs it. The Mac app shows the link's QR code once it's ready, in about 10 seconds.
4. **Clear old figures:** on the Lab page, press **Clear deliveries and payouts**.
5. **For phones:** scan the QR code in the PeerBeats Mac app, or send its link (**Copy Link**). Phones can be on any Wi-Fi or on mobile data, anywhere. Each phone chooses **Listener** or **Contributor**: listeners type `admin` for a free plan, contributors start sharing by themselves. Plug the phones in and keep PeerBeats showing. The link changes each time PeerBeats starts, so send the new one after a restart.
6. **Have a backup:** a screen recording of a good run.

## The demo

Use **Back to Lab** to move around. Nothing stops when you switch tabs.

| Time | Do this | Say or point out |
|---|---|---|
| 0:00 | Show the Lab page | The sentence above, then: "Each row is a different person." |
| 0:30 | Open **Contributor A**, **B** and **C**, or use phones | Each stores encrypted music. It can't play what it holds. |
| 1:30 | Open **Listener 1** and play a song. Press the bug icon | Each segment names who delivered it. The server sent the listener nothing. |
| 2:30 | Open **Listeners 2 and 3** and play other songs | Everyone is served at once. |
| 3:00 | Open **Monitor** | The delivery table shows the bytes each contributor sent each listener. Bold means sending now. Every figure is measured. |
| 4:00 | Close Contributor A's tab, or lock its phone | "Delivered by" drops it, and the music doesn't stop. |
| 4:45 | Close or turn off the rest | The label turns red, and within about 30 seconds the music stops. "This is what contributors are worth." |
| 5:45 | Turn one back on | The music resumes by itself within a few seconds. |
| 6:15 | On **Monitor**, press **Run payout now**. Show a contributor's **Earned** | Contributors share 60% of net revenue, by verified data. The rupees are simulated. |
| 7:00 | Open **New Listener**. Go to **Home** and play a song | Refused: the server won't give out the key. |
| 7:20 | On **Plan**, enter the code `admin`, buy Monthly, press **Pay** | A test checkout, with no real money. The song now plays. |
| 8:00 | Finish | Real payouts, licensing and hosting are the launch steps. |

If you have time, show **Library**, or add a track in **Catalog**: it reaches contributors straight away.

## If something goes wrong

| Problem | What to do |
|---|---|
| Contributors are online but nothing plays | Wait a few seconds: phones that can't connect directly switch to the relay by themselves. If it still won't play, check the contributor has finished storing (Contribute shows how much it holds). |
| A role opens in the same tab | The browser blocked a pop-up. Allow pop-ups for this site. |
| "Can't reach PeerBeats" | PeerBeats was quit, or its Terminal window closed. Open it again. Stored music is kept. |
| Earnings stopped rising | The test payments have been fully paid out. Buy a plan on the test checkout to add revenue. |
| Old figures from rehearsals | On the Lab page, press **Clear deliveries and payouts**. |
| Phone link won't start | The Mac needs internet. PeerBeats keeps trying by itself. Without internet, demo with laptop tabs only. |
